# AGENTS.md — Yumi Launcher

Инструкция для ИИ-агентов (OpenAI Codex и других), которые работают с этим репозиторием: что это
за проект, как его собрать и проверить, где что лежит и на какие грабли уже наступали. Прочитай
целиком до первой правки.

## Проект

- **Yumi Launcher** — лаунчер Minecraft для Windows на Kotlin/JVM и Compose Multiplatform Desktop.
  Дизайн — Material 3 Expressive, палитра Glacier, шрифт Roboto Flex, вместо картинки на фоне живой
  воксельный 3D-остров.
- Главная цель владельца — играть с друзьями без лицензии: офлайн-ник, аккаунт Ely.by, свой сервер
  на своём компьютере. Лицензионный вход через Microsoft тоже есть.
- Один Gradle-модуль `:app`, пакет `com.yumi.launcher`, точка входа `Main.kt`
  (`com.yumi.launcher.MainKt`).
- **Юнит-тестов нет.** Проверки — компиляция, headless-режимы и снимки экранов (см. «Проверки»).
- Что умеет лаунчер, подробно — в `README.md`.

## Сборка и запуск

На машине владельца (Windows, Git Bash):

```bash
source /e/Projects/.tools/env.sh                # JDK 21 и остальной тулчейн; без этого сборка не заведётся
export GRADLE_USER_HOME=C:/Users/000/.gradle    # тёплый кэш с артефактами Compose 1.11
./gradlew --offline :app:compileKotlin          # быстрая проверка, что всё компилируется
./gradlew --offline :app:run                    # открыть окно лаунчера («запусти демо»)
```

В другой среде (CI, облачная песочница): нужен JDK 21. Уберите `--offline` и две строки выше:
первая сборка скачает зависимости. `systemProp.https.protocols=TLSv1.2` в `gradle.properties` не
трогай — без неё Maven Central на сети владельца обрывает TLS.

**Установщик** — `./scripts/build-installer.ps1 -Offline` (PowerShell): `:app:createDistributable`
(образ приложения с Java внутри, `includeAllModules`), затем Inno Setup 6 по `installer/YumiLauncher.iss`
→ `dist/Yumi-Launcher-<версия>-windows-x64-setup.exe` и его SHA-256. `ISCC.exe` ищется в
`.local/tools/inno` (копия из YumiDesktop), потом в Program Files. Ставится для текущего
пользователя без UAC (`PrivilegesRequired=lowest`, `%LOCALAPPDATA%\Programs\Yumi Launcher`); при
удалении настройки, `%APPDATA%\YumiLauncher` и папка игры остаются. Версию меняй в двух местах:
`packageVersion` в `app/build.gradle.kts` и `AppVersion` в `.iss`. `AppId` установщика и
`upgradeUuid` не менять — по ним обновление находит старую установку. Проверка: тихая установка
в `.local` (`/VERYSILENT /DIR=…`), запуск установленного `YumiLauncher.exe --ui-smoke --only=…`
из отдельной рабочей папки, затем `unins000.exe /VERYSILENT`.

Ошибки компиляции ищи так: `./gradlew --offline :app:compileKotlin -q 2>&1 | grep "^e:"`.

## Проверки

После любой правки код должен компилироваться без ошибок. Дальше проверяй в зависимости от того,
что менялось. Все режимы запускаются через `--args` у `:app:run` или напрямую из тестовой копии
(см. ниже).

| Режим | Что делает |
|---|---|
| `--ui-smoke [--only=подстрока,…]` | Открывает окно и снимает все экраны в светлой и тёмной теме в `app/.local/screenshots/`: главная (и со свёрнутыми новостями, `folded-*` — свёрнуты и новости, и друзья; снимается вместе с предыдущим: `--only=news-hidden-,folded-`), сборки (список, каталог, редактор), моды, настройки, серверы, страница сервера (консоль, терминал с подсказками команд, настройки, баны), создание сервера, быстрый вход, вход Ely.by, главная с выбранным Microsoft (`ms-home-*`) и окно входа Microsoft (`ms-signin-*` — просит у Microsoft настоящий код); плюс главная и настройки в каждой пастельной палитре; плюс остров на каждом уровне качества днём и ночью с одной точки (`scene-<уровень>-<тема>`) и кадр посреди перелёта камеры (`scene-flight`). `accounts-*` — переключатель аккаунтов на главной, `downloads-*` — панель загрузок, `feedback-*` — обратная связь, `guide-<шаг>-*` — обучение новичка, `mods-shaders-*` и `mods-resourcepacks-*` — шейдеры (с карточкой «нужен Iris») и ресурспаки, `server-whitelist-*` — вайтлист сервера, `wheel-before`/`wheel-after` — остров до и после колёсика (камера «За мышью»), `fullscreen` — после F11 (нажимается настоящим `Robot`, второе нажатие возвращает окно). `pack-editor-launch-*` и `pack-editor-menu-*` — редактор сборки, прокрученный к «Запуску» и к «Меню игры», `quick-join-pack-*` — диалог «Сборка под сервер» для «Сервера Димы» (смоук поднимает его на 127.0.0.1:25599, `SmokeServer.kt`), `quick-join-packed-light` — после нажатия «Создать сборку» (сборка ставится в `.local/smoke-data`), `friend-pack-*` — «Зайти к другу» на Yumi-сервер без своей сборки (только с `YUMI_SMOKE_FRIENDS`, когда друг на сервере и подходящей сборки ещё нет: с ней окно сразу запустило бы игру), `settings-scene-*` — группа острова с «Во время игры», `settings-game-*` — группа «Игра» в настройках, `settings-key-*` — поле ключа CurseForge с отказом CurseForge на ключ-GUID (снимаются вместе с предыдущим кадром: `--only=settings-,pack-editor-`). `--only=server,scene-` снимает только кадры, в имени которых есть одна из подстрок. Настройки и данные — отдельные, пользовательские не трогает. **Обязателен после изменений UI**, снимки нужно посмотреть. |
| `--launch-test <версия> <папка> [загрузчик] [проекты Modrinth…] [--join=host:port] [--injector] [--menu=pink-dark-font]` | Без окна скачивает версию (и загрузчик, и моды), запускает игру, ждёт отрисовки и закрывает. `--join` — сразу зайти на сервер, `--injector` — под authlib-injector, как с аккаунтом Ely.by, `--menu` — поставить пак «меню игры» так же, как кнопка «Играть» (палитра, `light`/`dark`, `font`), и проверить, что игра его загрузила. |
| `--server-test <версия> <папка> [загрузчик] [порт] [--share=<папка с модами>] [--install=<папка>]` | Ставит сервер как экран «Серверы», запускает, пингует, выполняет `list`, выключает по `stop`. `--share` раздаёт эти моды как сборку сервера (метка в MOTD, как «Раздавать сборку»); после пинга печатает моды из пинга и план «Сборки под сервер», `--install` скачивает её моды. Для Forge положите моды в `servers/test-<версия>-forge/mods`. |
| `--ping-test <адрес…>` | Пинг серверов, как в «Быстром входе». |
| `--options-test <папка> [новый options.txt] [старый options.txt]` | Общие настройки игры без игры: выдуманные сборки во временной папке, первый запуск, изменения игрока, закрытый во время игры лаунчер, сборка со своими настройками, новая сборка, сборка до 1.13. С настоящими файлами оставляет слитый файл старой версии — его можно проверить `--launch-test`. |
| `--friends-test <адрес>` | Клиент друзей лаунчера против запущенного сервера друзей (`friends-server/app.py`): два выдуманных профиля, заявка, принятие, статус с игрой, сборкой и сервером, выход, удаление профилей. |
| `--world-test <папка>` | Без игры и загрузок проверяет создание сервера с копией мира сборки: измерения и данные модов, сохранность оригинала, новый мир, недоступный или занятый мир, очистку после ошибки и защиту от смешивания с миром из серверной части сборки. Данные — в новой подпапке указанной тестовой папки. |
| `--menu-packs <папка>` | Собирает пак «меню игры» во всех палитрах и темах плюс отдельный пак шрифта — zip-файлы для любой игры. |
| `--pack-test <архив.mrpack\|архив.zip> <папка> [ключ CurseForge] [--plan]` | Без окна ставит сборку из архива Modrinth или CurseForge в папку и переносит её моды на сервер, как импорт на экране «Сборки». С `--plan` (только CurseForge) ничего не качает: спрашивает CurseForge о файлах и печатает, сколько скачается в какую папку и что будет пропущено. |
| `--content-test <папка>` | Без окна, через ту же модель, что и кнопки: категории и сортировки обоих каталогов (CurseForge — если ключ есть в настройках), установка Iris, шейдера (Iris должен переключиться на него) и ресурспака (он должен появиться в `options.txt`), выключение, удаление; вайтлист выключенного сервера для всех трёх видов входа (офлайн-uuid, поиск аккаунта на Mojang и Ely.by, несуществующий ник); архив «Отправить лог» и вырезание секретов. Своя папка лаунчера и свой узел настроек. |
| `--scene-shot <папка> [качество…]` | Остров без окна: кадры на CPU в PNG, днём и ночью, с облёта и из кузницы, по умолчанию «Ультра» и «Высокое». Для работы над небом, облаками и туманом — окно не всплывает. Окно рисует то же на GPU. |

**Долгие проверки запускай из «замороженной» копии**, а не через `gradlew run`: иначе правка кода
во время прогона ломает перекомпиляцию, и тест падает не по своей вине.

```bash
./gradlew --offline :app:testBundle
cp -r app/build/test-bundle .local/test-bundle
java -Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -cp "E:/Projects/YumiLauncher/.local/test-bundle/*" \
  com.yumi.launcher.MainKt --server-test 1.21.1 E:/Projects/YumiLauncher/.local/server-test Fabric 25602
```

Правила для проверок:

- Тестовые данные — только в `.local/` (корня или `app/`), эта папка в `.gitignore`. Реальную
  папку игры владельца и узел настроек `com/yumi/launcher` не трогай.
- Тестовые серверы привязывай к `server-ip=127.0.0.1` (так делает `--server-test`). Иначе Windows
  показывает владельцу окно брандмауэра для `javaw.exe`.
- `--launch-test` и `--server-test` качают сотни мегабайт–гигабайты (игра, Java, серверы) и
  открывают окно игры на экране. Не запускай их без нужды и параллельно.
- Утверждай «работает», только если проверил реальным запуском. Если что-то не проверено (например,
  CurseForge без ключа или вход Ely.by без настоящего аккаунта) — так и скажи.

## Сервер друзей

`friends-server/` — отдельный маленький сервер на Python (только стандартная библиотека, SQLite в
`/data`), который хозяин лаунчера держит на Amvera; как его поднять — в `friends-server/README.md`.
Адрес для всех копий лаунчера — `FriendsApi.DEFAULT_URL` (https://friend-server-zakhuel67.amvera.io),
переопределяется в «Настройках» → «Друзья». Тесты против него создают настоящие профили — `--friends-test`
удаляет свои в конце, но не гоняйте его без нужды. Локально: `YUMI_DATA=.local/friends-data PORT=18080 python friends-server/app.py`.

## Данные на диске

- **Настройки** — `java.util.prefs`, узел `com/yumi/launcher` (на Windows это реестр). Смоук-режим
  пишет в `com/yumi/launcher-smoke` и удаляет его в конце.
- **`LauncherPaths.config`** = `%APPDATA%\YumiLauncher`: кэш (список версий, иконки, установщики,
  паки «меню игры»), `servers.json` — список «Быстрого входа», `game-options/` — общие настройки
  игры (`modern.txt`, `legacy.txt` для версий до 1.13) и `pending/<сборка>.txt` — снимок
  `options.txt` на момент запуска, пока изменения из него не ушли в общие.
- **`LauncherPaths.root`** — папка игры, которую выбрал пользователь (`settings.gameDir`; пока не
  выбрана, спрашивается при первом скачивании). Внутри:
  - `versions/`, `libraries/`, `assets/`, `runtime/` — общие для всех сборок;
  - `instances/<id>/instance.json`, `mods.json`, `minecraft/` — сборка и её папка игры;
  - `servers/<id>/yumi-server.json`, `server.properties`, мир, `mods/` — свои серверы;
  - `authlib-injector/` — jar агента.
- Форматы — `@Serializable`, читаются через `LauncherJson` (`ignoreUnknownKeys`). **Совместимость
  со старыми файлами обязательна:** у новых полей — значения по умолчанию, существующие не
  переименовывать и не удалять. Перечисления хранятся по имени. Значок сборки хранится индексом в
  `PackIcons`, цвет — в `PackColors`, форма — в `PackShapes` (null — вид, что был до выбора): в эти
  списки только добавлять в конец.
- **Шейдеры и ресурспаки** сборки — в `minecraft/shaderpacks` и `minecraft/resourcepacks`, то, что
  о них знает лаунчер, — в `instances/<id>/shaderpacks.json` и `resourcepacks.json` (у модов старое
  имя `mods.json`). Включённый шейдер — `shaderPack` в `config/iris.properties` (у Oculus —
  `oculus.properties`), включённый ресурспак — `file/<имя>` в `resourcePacks` из `options.txt`.
- **Аккаунты.** В настройках по одному аккаунту каждого вида в «слотах» (ник, сессия Ely.by,
  сессия Microsoft) и вид, которым играют, — с ними работают запуск, вход и обновление токенов.
  Остальные ждут в дочернем узле `savedAccounts`, по записи на аккаунт (у значения в prefs предел
  8 КБ); переключение меняет ждущий местами с тем, что в слоте. Токены ждущих не обновляются.
- **Лог лаунчера** — `%APPDATA%\YumiLauncher\logs\launcher.log` (прошлый запуск — `launcher.1.log`),
  архивы «Отправить лог» — `support/`, хранятся пять последних.

## Соглашения

**Код**
- Пиши так же, как написан окружающий код: те же имена, идиомы и плотность комментариев.
- Комментарии и KDoc — по-английски и объясняют «почему», а не пересказывают код.
- Тексты интерфейса — по-русски: «ёлочки», длинное тире, буква «ё». Ошибки для пользователя —
  короткая фраза о том, что случилось и что делать («Порт занят — возможно, сервер уже запущен»).
- Compose state меняется на главном потоке (`Dispatchers.Main` — это Swing EDT через
  coroutines-swing). Сеть и диск — в `withContext(Dispatchers.IO)`. Ожидание процессов, которое
  должно отменяться, — через `runInterruptible`.
- Навигация, которая должна пережить уход с экрана, живёт в `LauncherState`, а не в `remember`.
- Сеть — только через `core/Http` (повторы, докачка, User-Agent: Modrinth его требует).

**Интерфейс**
- Готовые компоненты: `Modifier.glass()` (плавающие панели над 3D-фоном), `ModalCard`,
  `ChoiceGroup` (соединённая группа кнопок-переключателей), `Hint`, `Label`, `PackTile`, `ShapeTile`,
  `SwitchRow`, `MemorySlider`, `RemoteIcon`, `RemoteImage`, `SkinHead`; для форм — `FormSection`
  (группа полей с заголовком), `ToggleRow`, `InfoChip`, `Tip`.
- Поля ввода — только `Field` и `SearchField` (`ui/components/Fields.kt`), не `TextField` напрямую:
  у них одинаковые фон, рамка и подписи во всех экранах, а наведение, фокус и ошибка видны в обеих
  темах.
- Кнопки — с `ButtonDefaults.shapes()` / `IconButtonDefaults.shapes()`. Ожидание —
  `LoadingIndicator`, прогресс — `LinearWavyProgressIndicator`.
- Окно без рамки (`undecorated`). Диалоги рисуются внутри окна через `ModalCard`, а не через
  `Dialog`/`AlertDialog`: у тех своё отдельное окно с лишней рамкой.
- Цвет содержимого (`LocalContentColor`) задан один раз наверху окна. Проверяй обе темы: в тёмной
  легко получить чёрный текст на тёмном.
- Цвета — только из `MaterialTheme.colorScheme`, без захардкоженных `Color(0x…)` в экранах: у
  лаунчера десять палитр (`settings.palette`: оригинальная Glacier и девять пастельных, одна из них
  почти серая — `Hues.chroma`) × светлая и тёмная тема. Пастельные схемы строятся в `ui/theme/Palettes.kt` из трёх
  оттенков OKLCH с общими шагами светлоты; новую палитру добавляй там же и в `enum Palette`.
  Исключения — цвета, которые не зависят от темы по смыслу: MOTD серверов, «онлайн»-точка.
- Ширина карточки экрана задаётся в `ScreenCard` (`LauncherApp.kt`): главная 440, моды, сборки и
  серверы 620, остальные 520 dp. Минимальный размер окна — 1100×720.
- Каждому разделу соответствует место на острове (`Section.spot`): моды — внутри кузницы, сборки —
  вид в библиотеку через открытую южную сторону, серверы — с земли на портал, настройки — костёр;
  главная — облёт всего острова. Карточка экрана слева, поэтому место в кадре смещено вправо
  (`offsetX` у точки камеры). Точки задаются через `lookFrom(глаз, цель)`; `pull` и `rise` —
  откуда перелёт заходит в место: сзади по линии взгляда и сверху. Для камеры внутри постройки
  подбирай их так, чтобы этот путь шёл через открытую сторону, а не сквозь стену или крышу.

## Известные грабли

- **Кодировка.** Русская Windows пишет вывод Java в cp1251. Процессам игры и сервера всегда
  передаются `-Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8`, вывод
  читается как UTF-8.
- **Лог игры — XML log4j**, а не текст; его разбирает `GameLog`.
- **Пути только ASCII.** Старые версии (LWJGL 2 на Java 8) не грузят natives из пути с кириллицей.
  Имена папок сборок и серверов делаются через `folderId()` с транслитерацией.
- **NeoForge** узнаёт jar игры по имени `${version_name}.jar`. Поэтому для версий с загрузчиком
  ванильный jar копируется в `versions/<id>/<id>.jar`, иначе игра грузится дважды и падает.
- **Forge/NeoForge-сервер** с 1.17 запускается строкой `java` из `run.bat` (файл `@…/win_args.txt`),
  старые — одним jar. `user_jvm_args.txt` пропускается: память задаёт лаунчер.
- **`server.properties`** пишется с `\uXXXX` для не-ASCII (иначе русский MOTD ломается на серверах,
  читающих Latin-1). До 1.14 режим и сложность — числами (`numericProperties()`).
- **Quick Play** (`--quickPlayMultiplayer`, 1.20+) в свежей папке игры ждёт экран настроек
  доступности. Для тестов в `options.txt` пишется `onboardAccessibility:false`. Версии до 1.20
  получают `--server`/`--port`.
- **Закрытие лаунчера** при работающем сервере идёт через подтверждение и `stopAll()`, плюс
  shutdown hook. Сервер не должен остаться работать без консоли.
- **Смена папки игры** переносит сборки и серверы. Пока работает сервер или идёт игра, смена
  запрещена.
- **Остров.** Он строится один раз при старте, в фоне (около трети секунды): текстуры, свет и тени
  запекаются, в кадре только проекция. Грани рисуются от дальних к ближним по числу шагов сетки от
  клетки глаза — поэтому всё на острове должно лежать в клетках сетки. Площадка постройки (`pad`)
  достраивает землю там, где выходит за край острова, иначе стена или фонарь повиснут в воздухе;
  деревья на площадках не растут. Что включается на каком уровне качества, решают
  `VoxelRenderer.draw` и `drawIsland` — новый эффект добавляй туда же и проверяй снимками `scene-*`.
  Целый куб скрывает грани соседей, поэтому в текстуре блока-куба не должно быть прозрачных
  пикселей — через них будет видно небо. Ореолы и блики прячутся за блоками, которые `screens`
  (кубы, ступени, плиты), иначе фонарь светит сквозь крышу.
- **Пак «меню игры».** Игра пишет все подписи белым, поэтому ни одна поверхность с текстом не
  светлая. Только спрайты GUI с nine-slice (с 1.20.2), без шейдеров — иначе конфликт с Sodium/Iris.
  У nine-slice посередине обязана остаться полоса: при нулевой середине игра падает на кнопке выше
  20 px (поэтому border 9, а не 10). Раскладку экранов пак менять не может — это код игры. Шрифт в
  игре один на всё, поэтому шрифт лаунчера — отдельный переключатель. Меняешь то, что рисует
  `MenuPack`/`MenuPanorama`, — подними `GENERATION` в `MenuStyles`, иначе останется старый кэш.
  Панораму проверяй в игре: грани 0–5 — вперёд, вправо, назад, влево, вверх, вниз.
- **Общие настройки игры.** Обратно в общие идут только изменения за игру (сравнение со снимком
  на момент запуска), а не весь файл: другая версия выбрасывает незнакомые настройки и ставит
  умолчания вместо значений, которых не понимает. Снимок живёт до следующего запуска любой сборки —
  лаунчер мог закрыться во время игры («Когда игра запустилась: Закрыть»). Файлу без строки
  `version:` дописывается версия из общих: без неё игра примет значения за формат до 1.13 и
  «обновит» названия клавиш. 1.13 ругается «Skipping bad option: lastServer:» на пустой адрес —
  безвредно.
- **Сборка под сервер.** Список модов сервер отдаёт только в Forge: `forgeData.mods` в 1.13–1.17,
  сжатое поле `d` (15 бит на символ) с 1.18, `modinfo` до 1.13; версия канала в `d` — строка до
  1.20.1 и varint позже, пробуются обе. Forge пишет «только сервер» без версии (или `OHNOES…`) —
  такие пропускаются. NeoForge отдаёт только `isModded`, Fabric и ванилла — ничего. ID мода ≠
  слаг Modrinth (`farmersdelight` → `farmers-delight`), поэтому слаги угадываются разбиением ID
  и проверяются одним запросом `/projects?ids=[…]` (он принимает слаги). Своя сборка сервера Yumi
  едет в MOTD после `

§8yumi1:` — клиент игры рисует две строки описания, остальное не видно;
  весь ответ пинга с иконкой должен влезть в 32 767 символов, поэтому метка ограничена
  `PackShare.MAX_TAG`. Сервер пересохраняет `server.properties` с `yumi1\:` — `ServerProperties`
  это читает. В форме настроек сервера метка скрыта (`PackShare.strip`).
- **Моды для сервера.** Серверной части сборки из архива верить нельзя: Fabulously Optimized помечает
  в `modrinth.index.json` все моды как нужные серверу, и в `server/mods` сборки попадают Iris и
  Sodium. Поэтому `ServerMods.sync` проверяет и её файлы (сторона на Modrinth по SHA-1,
  `environment` в `fabric.mod.json`). Моды «открыть мир друзьям» (`e4mc`, `world-host`) заявляют
  поддержку сервера, но на выделенном бесполезны — e4mc 6.2 роняет сервер 26.2 при входе игрока;
  они отсеиваются по id (`FOR_OPEN_TO_LAN`).
- **Друзья.** Ничего не уходит на сервер друзей, пока игрок сам не создал профиль. Статус — раз в
  30 с и сразу при запуске/выходе из игры и смене сервера (`snapshotFlow` в `FriendsModel`); сервер
  считает игрока ушедшим через 75 с, при закрытии лаунчера шлёт `offline` из shutdown hook. Сервер,
  на котором игра, берётся из запуска с «Быстрого входа» и из строки лога `Connecting to host, port`;
  свой сервер по `localhost` друзьям показывается адресом VPN (или локальной сети). С «Когда игра
  запустилась: Закрыть» лаунчер не работает во время игры — друзья видят игрока не в сети. Сервер
  пускает не больше 5 новых профилей в час с адреса — при локальных тестах перезапускайте его.
  Смоук показывает друзей, если задать `YUMI_SMOKE_FRIENDS="адрес|имя|токен"` (профиль на запущенном
  сервере друзей); иначе карточка «сервер друзей не подключён». Переменную задавай при запуске из замороженной копии
  (`java -cp`, из папки `app/`): через `gradlew run` она может не дойти до уже запущенного демона. Друг на `127.0.0.1:25599` — это
  «Сервер Димы» из смоука: на нём видна проверка сборки (`friend-pack-*`).
- **Сборка у друга на сервере.** `FriendServers` пингует серверы, на которых друзья (по адресу, раз
  при появлении и при каждом возврате на главную). Если сервер раздаёт сборку Yumi, план
  «Сборки под сервер» сверяется со сборками игрока: та же версия и загрузчик, и каждый мод плана
  лежит включённым в `mods` — по SHA-1 (кэш по размеру и времени файла), без хэша — по имени.
  Лишние моды не мешают. Под другом ничего не показывается: подошедшую сборку просто берёт «Зайти
  к другу», а без неё (или пока проверка идёт) кнопка открывает `ServerPackDialog` с целью
  `ServerPackTarget.Friend`: «Скачать и зайти» ставит сборку и сразу входит с ней, «Зайти так» —
  со своей; нашлась подходящая, пока окно открыто, — входит с ней. Для остальных серверов проверки
  нет: они не говорят, какая сборка нужна, и «Зайти к другу» входит сразу.
- **Вход Microsoft** идёт под client id официального лаунчера (`00000000402b5328`) через код
  устройства на login.live.com: `login_with_xbox` принимает токены Xbox только от одобренных Mojang
  приложений, а своё приложение Azure нужно отдельно согласовывать с Mojang. Токен Live уходит в
  Xbox как `RpsTicket: t=…` (`d=` — для токенов Azure, пробуется вторым). Токен игры живёт сутки;
  хранится refresh-токен Microsoft, и если до конца токена игры меньше часа, `MicrosoftAccount.fresh()`
  проходит всю цепочку заново. Профиля нет (404) — значит, у аккаунта нет игры или ещё не выбран ник;
  их различает `entitlements/mcstore`.
- **CurseForge.** Ключ API из console.curseforge.com — 60 символов, начинается с `$2a$10$`. GUID
  (`xxxxxxxx-xxxx-…`) — это токен загрузки или ID, CurseForge отвечает на него голым 403;
  `CurseForge.refused()` объясняет это игроку, поле ключа проверяет ключ запросом `/games/432`.
  Все GET к API — через `CurseForge.get()`. В `manifest.json` сборки `manifestType` —
  `minecraftModpack`. Файлы сборки берутся пачкой (`POST /mods/files`), папка — по `classId`
  проекта (12 — `resourcepacks`, 6552 — `shaderpacks`). У файлов, которые автор запретил качать
  лаунчерам, `downloadUrl` = null: их ищем на Modrinth по SHA-1 (`Modrinth.urlsByHash`), CDN в обход
  запрета не собираем. Если копии нет: мод останавливает импорт (без него сборка не запустится),
  а ресурспак или шейдер пропускается — сборка ставится без него, баннер «установлена» перечисляет
  пропущенное со ссылками и кнопкой папки (`SkippedFile`, `PackImporter.skipped`). `--pack-test` без ключа в аргументах берёт его из настроек лаунчера.
- **Небо «Ультра»** — три шейдера SkSL (`UltraSky`): небо со звёздами до острова, облака и море
  облаков после солнца и сияния, туман после острова. У острова нет буфера глубины, поэтому туман
  поверх острова рисуется только ближе острова (`front` — расстояние до него по лучу) и только когда
  камера снаружи. На программном рендере Skia (`GraphicsApi.SOFTWARE_*`) шейдеры не включаются —
  там они считались бы на CPU. Правишь шейдер — смотри `--scene-shot`: ошибку компиляции SkSL
  `UltraSky.create()` пишет в stderr и возвращает null, и «Ультра» молча рисуется по-старому.
- **Смоук и ввод.** `click()` и `wheel()` смоука кладут события в очередь AWT, а не вызывают
  `dispatchEvent`: код смоука работает внутри диспетчера Compose, и событие, обработанное на месте,
  заставляет Compose выполнить свою очередь — вместе с самой корутиной смоука — повторно. Итог —
  `CoroutinesInternalError … CompletedContinuation` и съёмка, которая молча стоит.
- **`Desktop.browse` на Windows** с Java 21 отдаёт любую ссылку браузеру по умолчанию — и `tg:` тоже,
  браузер открывается пустым. Ссылки открывает `Support.open` через `rundll32 url.dll,FileProtocolHandler`.
- **Картинки по URL** — только через `rememberRemoteImage`: состояние привязано к URL. С `produceState`
  место, которое стало показывать другое (выбранная сборка, строка меню), оставляло старую картинку.
- **Панель фильтров** справа от карточки рисует `LauncherApp`, а включает экран каталога: он кладёт в
  `LauncherState.filters` свой `FilterPanel` и убирает только его (сравнение по ссылке — при смене
  экрана новый успевает положить свой раньше, чем старый уйдёт). Поиск сборок живёт в
  `LauncherState.packSearch`, фильтры модов — в `ModManager` (`refilter` ищет заново для той же сборки).
- **Вайтлист.** Включённый сервер правится командами `whitelist on|off|add|remove` — файлы он пишет
  сам; выключенный — `whitelist.json` и `white-list`/`enforce-whitelist` в `server.properties`
  напрямую, uuid — офлайн (как у игры) или с Mojang/Ely.by по нику. Запускающийся или
  останавливающийся сервер не трогается. Вкладка перечитывает файлы раз в секунду.
- **Обучение новичка** (`Guide.kt`) находит, на что показывать, по `Modifier.guide(state, якорь)` —
  новый шаг — новый якорь там, где элемент. Шаг про раздел открывает раздел. Смоук ставит
  `guideDone = true`, иначе обучение закроет все снимки.
- **Отправка лога** ничего не шлёт сама: архив кладётся в буфер обмена файлом и открывается чат
  (`tg://` через реестр, иначе t.me). Бот с токеном в лаунчере не нужен и недопустим (секреты в коде).
- **`gradlew run` и правки кода.** Запущенное так демо грузит классы прямо из `app/build`: если
  пересобрать код, пока оно открыто, при следующем нажатии оно падает с `NoClassDefFoundError`
  (окно «Error» с именем класса вроде `ModManager$install$1`). После правок демо перезапускай.
- **curl из Git Bash** обрывает большие загрузки. Если качаешь руками — используй
  `/c/Windows/System32/curl.exe`. В коде качает `java.net.http.HttpClient`, с ним всё в порядке.

## Безопасность и приватность

- Пароль Ely.by никуда не сохраняется — только токены, в настройках. Не добавляй хранение паролей.
- Пароль Microsoft лаунчер не видит вовсе: вход подтверждается на сайте Microsoft. В настройках —
  refresh-токен Microsoft и токен игры.
- Ключ CurseForge — личный ключ пользователя из настроек. Никаких ключей, токенов и секретов в коде
  и в репозитории.
- Никакой телеметрии и отправки данных пользователя третьим сторонам. Сервер друзей — свой сервис
  владельца, и туда уходит только то, что игрок разрешил, после того как сам создал профиль.
- Ключ профиля друзей — как токен Ely.by: только в настройках; сервер хранит его хэш.

## Git

- `origin` — https://github.com/GXUser7/YumiLauncher.git, ветка `main`.
- `.gitattributes`: `gradlew` хранится с LF, `*.bat` — с CRLF, шрифты, картинки и jar — бинарные.
- Не коммить `.local/`, `build/`, снимки экранов и тестовые данные.
- Коммит и push — только когда владелец попросит. Сообщение коммита — по-английски: короткая
  первая строка, дальше что и зачем.

## Общение с владельцем

- Владелец пишет по-русски — отвечай по-русски.
- Он часто набирает текст в английской раскладке. Восстанавливай раскладку сам и не переспрашивай:
  `pfgei` → «запуш», `pfgecnb ltvj` → «запусти демо», `gjlcjtlbyb ubn` → «подсоедини гит».
- «Запусти демо» = `./gradlew --offline :app:run` в фоне (с `source` и `GRADLE_USER_HOME` выше).
  У владельца есть и ярлык «Yumi Launcher (демо)» на рабочем столе: `scripts/run-demo.vbs` →
  `scripts/run-demo.cmd` (без консоли, лог в `.local/demo.log`); пересоздать —
  `scripts/make-shortcut.ps1`. В среде агента задана `NoDefaultCurrentDirectoryInExePath=1`:
  в `.cmd` вызывай программы по полному пути, текущая папка не просматривается.
- В ответе: что сделано, что проверено и чем, что не проверено. Без воды.
